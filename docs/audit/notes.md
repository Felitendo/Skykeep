## Details

### 1. Ctrl+N after creating a note duplicates it
Repro (from reading the code): New Note, type "Groceries", pause 1 s (`commitComposing` sets `adoptedKey.current = guid`; the editor key stays `"composing"`), then press Ctrl+N. `create()` sets `composing` and `openGuid=null`. The key at `:1503` is still `"composing"` and `canEdit` stays true, so `<NoteEditor>` is not remounted and still contains "Groceries". `autoFocus` and `placeholder` apply only at mount. Typing "x" calls `apply` → `setComposing({body: "Groceries…x"})`, and 900 ms later `noteCreate` makes a second note holding the first one's text.
Fix: in `create()`, `adoptedKey.current = null;` before `setComposing(...)`.

### 2. Formatting wiped when typing just after opening
- `canEdit` (`:872`) requires `body !== null` only.
- First key with runs still null: `base.current = {text, runs: null}` (`:470`), `pending.runs = null`.
- Runs arrive. The `adopted` effect is skipped because `pending` is set. `formatSafe` becomes true.
- Next key: `pending.runs = typedRuns`. These come from the plain document the editor was mounted with.
- `flush` sends `runs=plain`, `baseRuns=null`. `record_note_save` fills `base_runs` from the stored (Apple) runs. `keep_their_formatting` then sees every line changed from formatted to plain and writes plain to Apple.

The window is the gap between the `noteBody` and `noteRuns` IPC calls. It is small, but the result cannot be undone. A single `note_open` command that returns both closes it, and also removes the plain-then-formatted repaint in #4.

### 5. One network request per attachment on every open
`attachmentView` → `api.noteTable(id)` → `note_table` → `table::stored` misses for any non-table attachment → `cloudkit_context` + `lookup_record("Notes", id)`, and nothing is cached when the result is `None`. Only then does `showMedia` → `describe` (cached on disk at `main.rs:526`) run. A note with 6 photos therefore makes 6 CloudKit requests before any picture starts loading, every time it is opened. Offline, each request has to fail first. Swapping the order (describe first, table only when `kind === "table"`) makes cached notes draw their pictures straight from disk.

### 6 and 7. Typing cost
Per key today: a full `fromDoc` walk, then 3 or 4 React state updates in `NotesView` (`draft`, `edits`, `saved`, `status`). Each re-renders the folder column and every note row. Every 900 ms pause also runs `write()` → `busy` → `read()` (3 IPC calls and a full list diff), and then the outbox tick runs it again with `noteBody` + `noteRuns`. Memoising the list, comparing status before setting it, and having `flush` call `noteSave` directly should take a key back to one small re-render of the editor header.

### 8. Attachment speed
Critical path per file today: grant → `lookup_record` → upload asset → `lookup_record` → `records/modify` → **`resync_notes`** → return. Then `noteBody` + `noteRuns` + `read()`. Moving the resync into the background and using the returned `body` should leave about 3 round trips plus the upload.

---
**Summary**
1. Two real data bugs: Ctrl+N after a new note duplicates it (#1); typing before runs load, or in a just-created note, can wipe or drop formatting on Apple (#2, #3).
2. Slow opening comes from a CloudKit request per attachment on every open (#5), the spinner, plain and formatted repaint sequence (#4), and attachment adds that wait for a full sync (#8).
3. Typing latency on large accounts comes from whole-screen re-renders per key and a list reload on every autosave (#6, #7). All fixes are small and local.
